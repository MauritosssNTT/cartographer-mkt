# Knowledge Market documentation

This directory describes the implemented behaviour of the Knowledge Market demo and the
rules used to evolve it.

## Reading order

1. [Architecture](architecture.md) explains the application boundary, runtime paths and
   data flow.
2. [Development guidelines](development-guidelines.md) defines the working agreement for
   changes generated or assisted by coding agents.
3. [Domain glossary](../CONTEXT.md) defines the vocabulary used by the product and code.
4. [Architecture Decision Records](adr/) capture durable, non-obvious technical choices.

## Documentation policy

Documentation describes the current state; Git history preserves the chronology. Update the
relevant page with the code change. Create an ADR only for a difficult-to-reverse choice that
has meaningful alternatives and would otherwise be surprising to a future contributor.
